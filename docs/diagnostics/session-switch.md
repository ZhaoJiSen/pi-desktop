# 快速切换会话时的插件上下文失效

## 证据与边界

截图中的 `This extension ctx is stale after session replacement or reload` 对应本机 Pi 的扩展上下文失效检查。会话替换会销毁旧运行时；插件捕获的旧 `ctx` 随后调用 API 会抛错。源码片段 `extractSpawnMarker` 来自已安装的 pi-lens 4.4.3，但这并不能单独证明违规回调就是 pi-lens 创建的。

隔离 HOME、agent 设置和项目，在真实 Pi 上测试：只加载 pi-lens，空闲状态连续 8 次 `new_session` 均成功。再添加一个最小故障扩展，在 `session_shutdown` 后通过异步回调访问旧 `ctx.isIdle()`，复现相同报错并导致进程以状态 1 退出。因此这类错误可能损坏连接，单纯隐藏通知不足以解决。实验不发送模型请求，不使用真实凭据，不修改用户插件或全局设置；完整用户扩展组合下的原始触发条件尚未复现。

## 修改

- 连接请求使用序号，等待中的过期请求退出。正在执行的替换仍完成必要的绑定更新，之后跳过已过期的元数据工作。31 次快速选择测试只发生首次和最后一次必要的替换。
- 只识别错误行开头的已知 stale-context 错误，不将源码中的同名字符串误认为故障。仅在已发生会话替换且没有运行中的前台任务时自动恢复一次；恢复失败显示真实错误，没有自动循环重试或消息重发。
- 出现该故障的项目与执行文件组合，在本次前端运行期间使用进程重启切换，避免再次在损坏的扩展生命周期中热替换。其他项目保留进程复用。进程数量仍为每项目一个；问题项目的切换成本可能增加。兼容标记不写入用户设置，重启应用后重新判断。
- stdout 退出与 stderr 错误可能乱序。仅保留最后一个退出的前台进程绑定，允许迟到的已知错误触发恢复；新进程已连接时忽略旧进程的迟到错误。
- 通知排除 Node 堆栈和整行打包源码，保留真实错误，单条诊断限制为 500 字符。
- 修复较早的取消结果回滚较新会话选择的问题。

## 验证

6 个定向测试文件、105 项通过：desktop、runtimeDiagnostics、piUpdates、useDesktopLifecycle、inlineQuestions、runtimeNotice。覆盖快速切换、旧回复隔离、错误先于或晚于进程退出、单次恢复、恢复失败、草稿保留、项目隔离、运行中任务不重启、不重发提示词以及真实错误保留。lint 和差异空白检查通过。未进行生产构建；未在用户当前原生窗口和全部真实插件组合中复测。
