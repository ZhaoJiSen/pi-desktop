# HeroUI Review Composer 落地

北极星：先选任务、编辑可见消息，发送前可检查；会话状态独立放在输入下方。沿用项目主题、系统字体、Lucide 图标和正文 15px/22px。参考：https://heroui.pro/docs/react/components/prompt-input#review-composer 。不增加图片或装饰色。

## 实现

- 输入主体改为已安装 @heroui/react 的 TextArea（实际 DOM 为 textarea，data-slot=textarea），完全移除旧 contentEditable、手动 Range、尾部 BR、标签参数编辑器及自定义编辑历史。
- 六个职责分别为 Composer 调度、ComposerInput、ComposerToolbar、ComposerPrompts、ComposerStatus、ComposerAttachments；继续复用 SlashCommandMenu 与 ModelSelector。
- 短输入 52px；折行/换行/附件/窄栏改为上方输入、下方工具栏；最大输入高度176px。独立隐藏测量元素算高度，不反复清空实际 textarea 的高度，键入时不接管原生滚动和撤销；恢复长草稿或填入提示词时一次性滚至末尾，避免选区在末尾而视口仍停在顶部。
- 上方快捷按钮为审查改动、生成提交说明；更多里有解释代码、先做计划、补充测试和现有提示词目录。窄栏将第二个快捷入口收进更多，输入提示缩短。
- 空草稿点击提示词后直接填入；已有内容先展开预览，选择追加或替换。不会自动发送，也不会执行分支或提交动作。输入可编辑、附件保持。
- 旧命令标签直接显示为 /命令 参数 文本，编辑时保留命令来源与执行校验；发送侧仍复用 live catalog 校验。内置命令继续打开对应控件，终端命令继续报错。无关文本、代码块及路径不转命令。
- 分支/用量在底部独立一行，用量按钮可以展开详情；不再使用绝对定位贴边框。保留对象名称、状态和操作；移除内联标签的删除/参数编辑文案展示。

## 动效与检查

快捷按钮短促按下反馈，预览160ms淡入，首次进入200ms淡入并移动5px，发送按钮保留按下和 pending/stop 反馈。减少动态效果时取消新增位移与过渡。没有添加循环装饰动效。

局部自检一轮，未做独立评审。实际看过浅色、深色 Nord、窄栏、提示词预览和200% CSS zoom截图。菜单模板说明最初被全局 .button.menu-row 的固定高度覆盖，已提高局部选择器优先级并确认正常。截图复查还发现附件规则被展开规则覆盖，已修正并新增附件必须在输入上方的几何断言。

verify.mjs 最终版本连续第1/2/3轮（seed80/81/82）通过，详见results.json：

- 确认真正的HeroUI原生textarea、没有contenteditable；上方快捷操作与下方状态位置独立；短输入52px。
- 内置提示词填入、已有草稿预览/追加/替换、刷新保存恢复；既有 /plan 模板插入普通文本。
- / 联想选择、/model 打开模型面板并切换模型、/login 保留草稿显示错误、编辑清错。
- 原生按键持续40次Shift+Enter，不重新指定焦点；逐批检查临界高度、选区、滚动和页面位置；继续输入、Backspace、原生撤销重做、返回开头编辑。
- 保存失败保留当前输入，恢复后持久化；旧命令草稿迁移；附件移除且提示词替换不影响附件。
- pending加载、运行中Stop和快捷操作禁用、模拟运行完成；320px容器深色布局和用量详情。

200%额外检查同样连续40次换行后输入x，textarea176px、选区41、scrollTop距最大距离2.5px以内；见zoom-results.json。早期双轮验证工具调用超时，未记录为最终通过；最终逐轮独立保存结果。

类型检查、lint、git diff --check通过。旧编辑器测试替换为原生输入行为和命令迁移用例；按skill未执行生产构建或全量测试。原生撤销检查在输入/删除之间移动一次光标，显式形成撤销分组边界；直接快速输入再删除可能被浏览器合并为净变化为零的同一组。实际浏览器操作为主要交互证据；验证使用真实组件与隔离的sessionStorage，未发送模型请求。

## 限制

当前应用控制工具无法识别桌面调试窗口，启动现有调试程序后仍无法连接，因此未完成原生桌面WebView复测，未宣称原先点状光标在原窗口已被实际复现并消除。旧编辑器的Range/手工滚动路径已移除。临时启动的调试进程已清理，未运行构建。
