# 能力库与快捷入口修正

## 方向
沿用 Pi Desktop 的 HeroUI 控件、主题变量、紧凑左列表/右详情。北极星：用户能直接看懂“这是什么、会影响哪条消息、在哪里管理”，常用设置操作后立即留下可靠结果。

## 本轮调整

1. 来源和类型筛选继续使用 HeroUI Select。协调触发器高度、上下内边距和文本行高，解决压缩外框后字形被切掉的问题；常规尺寸和 CSS 2× 阅读尺寸均查看过。
2. 宽栏只在右侧内容区显示一组居中空状态；窄栏在当前可见列表区域居中显示，不再左右重复。
3. 聊天 `/` 建议同时过滤停用、缺少来源、同名覆盖、桥接不可用、计划模式冲突和仅限终端的命令。断开连接时不提供不可执行选项。手动发送停用项仍拦截，保留正文；同名资源只提供实际生效的来源。
4. 快捷入口设置的开关、数量、键盘/拖拽排序及移除均自动保存。移除原 Save 栏，提供保存状态；失败保留当前修改并提供“重试保存”。自动保存合并连续更新，单次写入失败回退已保存状态，不冒充保存成功。
5. 管理入口整理为设置底部的独立“能力库”设置行，带具体说明和“打开能力库”按钮。Pi 连接中的恢复操作改为始终有表面的次级按钮“使用默认命令（pi）”。连接路径仍由“保存并重新连接”提交，避免输入中途重连。
6. 预置名称调整为“代码审查”“计划模式”“代码讲解”“生成测试”；明确“用于下条消息”“允许在聊天中使用”“添加到快捷栏/从快捷栏移除”。旧版本标准名称按已知值兼容替换，用户自定义名称保留。任务详情删掉重复的“使用方式”，保留类型、来源、斜杠入口、生效范围和主操作；原生命令继续显示执行/导航/终端语义。
7. 新建与编辑改用 HeroUI Modal，保留完整的内侧焦点轮廓。编辑只提交一次；失败留在弹窗并保留填写内容。关闭返回原详情。弹窗的表单提交仍是明确的保存操作，与快捷入口的自动保存分别处理。

动效沿用现有 Motion 的列表/详情短过渡、按钮按压及拖拽弹簧，弹窗使用 HeroUI 自带进出场。未添加宽高动画；减少动态效果夹具下检查入口与关闭。

## 验证
主 Agent 通过 CUA 操作生产组件与隔离 Pi IPC 夹具；数据存储使用独立 sessionStorage 前缀，不编辑用户配置。最终连续第 **11、12、13 轮全部通过**，结果见 `ui-results.json`，可复查脚本为 `verify-ui.mjs`。

覆盖：筛选文本完整行高、桌面与窄栏空状态、中文编辑、键盘焦点、表单保存失败/恢复/刷新读回、新建弹窗取消、快捷数量自动保存与刷新读回、真实指针拖拽及键盘排序、自动保存失败保留修改/重试/刷新读回、管理入口、连接操作按钮、同名命令冲突、仅终端命令隐藏、断线菜单清空、停用项建议过滤及手动发送拦截、窄栏弹窗关闭和减少动态效果。

类型检查（应用、scripts、tests 三个项目）、lint、差异空白检查通过。未运行生产构建、全量或单元测试；本轮未改原生代码。实际原生 WebView、远端模型与真实插件执行未重测，夹具验证不等同于这些集成验证。

## 视觉评审与减法
独立评审一轮，采用存量界面润色标准，不打分。未发现必须修改的视觉问题。已采纳删除任务详情重复“使用方式”的建议，保留既有 Nord 主题和目录结构。没有添加设计规则忽略项。

主 Agent 另外发现并修正：弹窗主按钮文字对比、管理入口前重复分隔线、窄栏空状态未占满剩余高度。删掉重复空状态、Settings Save 按钮、含糊的固定/桌面启用文案；对象名称、来源、范围及错误原因保留。

## 证据
截图均为 1280×720 浏览器，使用实际生产组件。`empty-light-narrow.png` 的内容容器宽 480px，不是 480px 浏览器窗口；`reading-css-200.png` 是 CSS 2× 阅读检查，不是系统缩放。

- `library-dark.png`：最终目录、完整筛选文本与语义操作。
- `empty-dark.png`：桌面内容区单一居中空状态。
- `empty-light-narrow.png`：浅色窄栏居中空状态。
- `editor-dark.png`、`editor-light.png`：深浅编辑弹窗与焦点轮廓。
- `shortcuts-dark.png`：设置底部管理入口与自动保存状态，已滚动以显示状态。
- `connection-dark.png`：默认命令的常驻按钮形态。
- `reading-css-200.png`：放大阅读下筛选与列表。

没有录屏接口，未伪造录屏或帧率结论。部分弹窗背景仍为减法前的详情字段，弹窗/表单本身未再变更；最终详情以 `library-dark.png` 为准。
