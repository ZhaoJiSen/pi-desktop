# 暗色聊天对比度检查

2026-10-18。用户要求检查暗色聊天页；本轮只诊断，不修改产品源码。

## 范围与依据

逐张查看用户提供的三张截图；使用当前真实组件、隔离的内存存储和同一份聊天内容，对 Tokyo Night、Rosé Pine、Linear Dark、Ayu 拍摄 1512×1076 实际页面。聊天内容是检查用固定数据，未连接模型。另对全部 11 套暗色主题计算颜色组合。截图未验证发送、保存或动态扫光。

设计目标：正文保持阅读中心；思考与工具过程退居次级，但仍可读；代码、表格、用户消息能被快速区分；保留各主题色相、布局、字体和输入框的单块表面。

普通小字的参考门槛为 WCAG 4.5:1。面板底色之间的低差异属于层次问题，不能把所有面板底色都按 3:1 判为不合格；必要的控件识别信息才应用相应非文本对比要求。

## 主要发现

| 主题        | 正文 / 聊天底色 | 辅助文字 / 聊天底色 | 输入提示 / 输入框 | 主要问题                                                                      |
| ----------- | --------------- | ------------------- | ----------------- | ----------------------------------------------------------------------------- |
| Tokyo Night | 10.59:1         | 7.04:1              | 5.79:1            | 字可读，但代码底色与页面约 1.05:1，表格及工具行层次偏平                       |
| Rosé Pine   | 13.39:1         | 7.05:1              | 5.69:1            | 工具边界弱，行内代码与表格表面接近；代码底色与页面约 1.07:1                   |
| Linear Dark | 17.90:1         | 7.79:1              | 6.29:1            | 正文强，表面变化很轻；用户消息、表头与代码共用一个底色，差异约 1.09:1         |
| Ayu         | 9.81:1          | 3.07:1              | 2.61:1            | Thinking、工具状态、元数据、代码注释与复制图标过暗；代码底色与页面仅约 1.04:1 |

输入提示数值按当前 CSS 的 ink 9% + paper 91% 默认输入框填充计算，未套用 hover 状态。全量数据保存在 contrast.json；截图工具也在 Ayu 实际页面检出 13 处低对比文字。不可把禁用发送按钮当作普通可操作控件判错。

### P1：Ayu 辅助信息可读性不足

--muted 为 #5a6378。Thinking、工具次数、已完成状态、输入提示、用量信息、代码注释与复制按钮共用它。在 #10141c 页面上约 3.07:1，在稍亮的输入表面上更低。问题源头是颜色角色直接复用编辑器中偏暗的注释色；只是增加卡片边框不能解决文字难读。

目标：可读的辅助文字及输入提示至少达到 4.5:1，图标按实际控件用途检查；保持正文更突出。

### P2：代码、表格和工具容器的层次不足

Tokyo Night 的 code-head #16161e 比 paper #1a1b26 更暗；另三套则稍亮，但距离都很近。code-head 同时供行内代码、表头和整块代码使用，一处调整会影响多个层级。工具默认透明，仅用 --line 轮廓：Rosé Pine 边线与页面约 1.16:1，Ayu 约 1.12:1。这里是实际扫读感受与视觉组织问题，不应仅用文字对比合格来判定设计完成。

目标：保留暗色气氛，给代码阅读区域、行内代码、工具交互区域明确且克制的区分；不增加每层描边，不抬亮整张聊天页。

### P2：主题移植缺少聊天场景的统一验收

其余主题还发现：One Dark 辅助文字/页面约 3.98:1，输入提示约 3.34:1；Min Dark 输入提示约 3.70:1；Gruvbox 输入提示约 4.21:1。Nord 与 Gruvbox 部分语法颜色在代码底色上的最低值分别约 3.74:1、3.82:1，需要复核具体语法用途。它们来自同一套角色复用策略，修复时应覆盖全部暗色主题。

## 建议修改顺序

1. 先修 Ayu、One Dark、Min Dark、Gruvbox 的辅助文字/输入提示；分别检查默认、hover、展开内容和有内容输入状态。
2. 在现有设计变量中分清聊天辅助文字、输入提示、代码阅读表面、行内代码与工具交互边界的用途；只在需要不同表现时拆开角色。
3. 按各主题自身色相提高表面层次，保留正文颜色、现有字号、左基线、工具默认折叠行为和输入框布局。
4. 使用本目录同一份聊天内容复查全部暗色主题，并补工具展开、运行、错误和长代码滚动状态；避免只看设置中的微缩预览。

## 独立评审

一轮无历史上下文、只看截图及完整 DESIGN.md 的存量界面评审，不打分。评审确认用户图 3 的 Thinking、工具状态、输入提示、用量信息过暗，行内代码区分偏弱；建议保留正文排版、输入框抬起表面和既有表格结构。评审没有从截图推断主题 ID，没有估算数值。完整代码块和运行状态不在用户图中，相关判断由主 Agent 的本轮实际代码截图及色值计算补充；动态状态仍未验收。
