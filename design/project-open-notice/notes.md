# 打开项目失败的提示

空会话的主角是标志和输入框。`Could not open the project directory` 是一次已经结束的操作：目录不存在，当前会话没有断。原先把它写进 `connectionError`，于是输入框上方出现一条可关闭的红条，并带上「重新连接」。重新连接不会把缺失的目录找回来。

VS Code 把打不开文件夹放在角落通知，默认右下角，因为中间是编辑器、底下有状态栏。Cursor 把聊天通知从右下角挪开，避免挡住输入。Claude 和 ChatGPT 不在空会话的标志和输入框之间放红条；一直成立、需要恢复的状态才留在输入附近。

这里没有状态栏，发送按钮在输入框右侧，非阻塞通知已经在右上。所以这条失败用右上角通知：产品句子做标题，系统原因做第二行，8 秒后离开，可关闭。不提供重新连接。

pi 进程退出、尚未连接、本地保存失败仍用原来的提示条。这些状态还在，恢复动作是重新连接。

窄窗口的通知让开 48px 导航轨。`(os error N)` 整段不拆行。
