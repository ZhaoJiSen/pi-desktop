# Prompt Input 视觉优化

## 方向

轻量的双层写作面板：正文为主，参数为辅，发送是唯一主动作。用户已给定 HeroUI Pro Prompt Input 参考，并要求保留原有显示，因此只深化当前方向。

参考：https://heroui.pro/docs/react/components/prompt-input 。已通过浏览器查看 Default、Secondary 和相关示例入口。借鉴内容区/工具栏起止区的分层与控件表面，不照搬占位文案、免责声明或新增队列功能。

## 具体调整

- 保留上沿分支、Context、Token、费用；保留附件、命令标签、模型、思考强度和发送/停止入口及原顺序。
- Composer 分出 composer-content 与 composer-toolbar-start，发送仍在工具栏尾部。继续使用既有自定义 DraftEditor、HeroUI Button / Popover；没有切换到 Pro TokenInput，也没有新增依赖。
- 模型和思考强度变为 34px 浅表面胶囊；附件/发送仍为 34px 圆形。短输入维持 94px，带命令标签约 95px，编辑区上限继续为 176px。
- 减轻外框阴影；命令标签使用紧凑胶囊，来源与名称用细分隔区分；附件采用统一圆角和紧凑内边距，保留文件名及移除按钮。
- 窄容器使用 container query，保持全部操作可见；思考强度不压缩，优先省略模型名，并在文字上保留原始全名 title。截图自查发现强度曾被压缩，已修正选择器优先级并增加可见宽度断言。
- 等待连接、读取附件、提交时，发送按钮使用 HeroUI isPending + Spinner；空输入用较安静的禁用表面；运行中保留停止图标。
- 命令错误沿用原文案与既有状态逻辑，改为危险色浅底提示。编辑后仍清除错误，原草稿不丢失。

## 动效与减法

保留原有首次进入 250ms/50ms 延后、发送按下 80ms/.97、浮层展开；控件 hover 120ms，等待状态使用 HeroUI Spinner。没有新增装饰动画，没有删改界面文字。减少动态效果规则仍然有效，本次未覆盖浏览器媒体偏好做行为测试。
